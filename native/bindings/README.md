# Native binding generation

All low-level InnoEngine native imports are generated by BindGen-CS. The checked-in C# output is a reproducible build artifact; do not add or edit `DllImport`, `LibraryImport`, or `extern` declarations by hand.

## Workspace

`workspace.json` is the single entry point and currently owns five binding projects:

| Config | Upstream API | Output project |
| --- | --- | --- |
| `cimgui.json` | cimgui | `Inno.Native.ImGui` |
| `imguizmo.json` | cimguizmo | `Inno.Native.ImGuizmo` |
| `miniaudio.json` | miniaudio | `Inno.Native.MiniAudio` |
| `sdl3.json` | SDL3 | `Inno.Native.Sdl3` |
| `bgfx.json` | bgfx C99 | `Inno.Native.Bgfx` |

Library-specific API spelling and deliberate omissions belong in the JSON configuration and its companion API-shape files. Reusable ABI behavior belongs in BindGen-CS. Generated output must never contain library-specific manual patches.

## Commands

From the InnoEngine repository, with BindGen-CS checked out next to it:

```bash
dotnet run --project ../BindGen-CS/src/BGCS.Tool/BGCS.Tool.csproj --configuration Release -- workspace generate native/bindings/workspace.json
dotnet run --project ../BindGen-CS/src/BGCS.Tool/BGCS.Tool.csproj --configuration Release -- workspace diff native/bindings/workspace.json
```

The complete acceptance gate is owned by BindGen-CS:

```bash
cd ../BindGen-CS
bash scripts/test-innoengine-bindings.sh
```

That gate requires a clean workspace diff, rejects hand-authored native imports outside `Generated/`, builds every required native dependency from its pinned source, builds the complete InnoEngine solution, and runs every native binding test project.
